## 1. 整体方向：精密、轻盈、有反馈

将 FX 练习室做成有辨识度的**浅色交易工作台**：墨色品牌、清楚的主报价、大幅图表、安静的账户概要、浅语义交易按钮，以及及时而短促的操作反馈。

主要视线路径为 **当前品种与报价 → 图表走势 → 下单或持仓结果 → 回放 → 成交记录**。权益说明资金状态，图表用于判断，邻近交易区用于执行，各部分按职责分配视觉权重。

精致感来自五项统一处理：

1. **比例有主次。** 权益突出，其他账户数字较小；Bid 是主读数，Ask 保持可见；持仓时平仓成为交易区主动作。
2. **表面有层次。** 外围淡灰、主图纯白、交易区极浅灰，通过留白和细线连接。
3. **细节有尺度。** 数字、单位、图标、控件、分隔和对齐线遵守相同规则。
4. **操作有回应。** 悬停、按下、选中、输入、展开和开平仓各有短反馈，状态立即生效。
5. **边缘状态完整。** 首根行情、空持仓、无记录、保存失败和恢复暂停都有清楚的布局与动作。

浅色方向兼顾长时间看图和新手理解。持续闪烁、装饰渐变、玻璃折射、大面积阴影及庆祝动画会增加视觉负担，不改善本项目的交易操作。

## 2. 改版依据

改版前检查了工作台、共享样式及账户、图表、回放、交易、记录、帮助组件，并查看了实际桌面页面。以下为设计判断与对应改动，不代表竞品易用性或性能测评。

| 改版前的问题 | 对阅读与操作的影响 | 采用的处理 |
| --- | --- | --- |
| 五个账户数字几乎等权 | 首屏像平均分栏的报表，难找重点 | 权益与其他指标分级，数字与单位分开 |
| Bid、Ask 同字号、同色 | 缺少稳定的主报价 | Bid 主读数、Ask 辅读数，点差独立 |
| 品牌蓝出现在大量文字和入口 | 主色难以突出关键动作 | 墨色品牌，蓝色集中用于播放、选中、焦点及当前价 |
| 红绿实色方向按钮占据大块侧栏 | 下单按钮压过持仓结果 | 浅语义底色，持仓盈亏与平仓入口突出 |
| 品种、报价和图表读数较分散 | 工具齐全但整体层次弱 | 顶部工具条、报价、读数、画布和回放连成一个区域 |
| 反馈主要依赖背景变色 | 动作完成与状态切换不够明确 | 固定反馈位置，短过渡及明确焦点 |
| 窄屏沿用桌面轴标签密度 | 小屏读数拥挤 | 按图表真实宽度减少标签，保留字号 |

沿用本地字体、SVG 图标、同一 ECharts 实例、手机成交详情与键盘帮助；交易规则、行情可见范围和本地数据边界保持由原有模块负责。

## 3. 设计研究与取舍

本次核对 **19 个官方页面，覆盖 9 个产品与 4 套设计体系**。资料类型、核对方式及限制见 [界面设计研究](../knowledge/04-interface-design.md)。

| 参考组合 | 采用的手法 | 在本项目的落点 |
| --- | --- | --- |
| TradingView、Coinbase Advanced、IBKR | 看盘、执行、结果有稳定空间分工 | 主图、邻近交易区、下方成交记录 |
| Mercury、Wealthfront | 大数字与辅助数字明显分级 | 权益、Bid、持仓盈亏有各自的视觉重点 |
| Linear、Raycast | 紧凑控件、集中动作、按需说明 | 统一工具条高度，帮助与反馈贴近操作 |
| Koyfin、Stripe | 数据对齐，内容与动作共享上下文 | 金额与单位分级，记录列对齐，恢复动作就近提供 |
| Atlassian、Radix、Carbon、Apple | 有序状态色阶、短反馈、可访问性及动效边界 | 共享视觉变量、按钮层级、可见焦点、减少动效 |

复杂导航、真实交易、云服务和分析报表超出本次范围。官方页面用于研究构图；项目没有复制竞品界面资产或代码。

## 4. 整页构图与模块设计

品牌栏、账户条、图表与交易区、成交区共用边距和对齐线，形成连续工作台。图表取得主要宽度，桌面下单区紧邻行情；空间不足时交易区移到图表下方，手机再改为单列。内容随文字放大自然增高，具体尺寸和断点只在 [产品与设计](01-product-and-design.md#当前工作台布局) 维护。

品牌使用墨色小型 FX 标识，记录锚点与保存状态位于右侧。保存状态位置稳定，失败时持续显示恢复入口。页面文字围绕看盘、交易和理解结果，研究说明保留在文档中。

| 模块 | 设计重点 | 保留的业务边界 |
| --- | --- | --- |
| 账户 | 权益为主，其他指标与单位分级；按可用空间重排 | 资金概念与计算来自账户状态 |
| 报价 | Bid 为主、Ask 为辅，点差独立；Bid 尾部两位用固定蓝色表达精度 | 完整报价保留；固定蓝色不作为涨跌信号 |
| 图表 | 低对比网格、右侧价格轴、稳定读数、当前价标签；标签碰撞时避让 | 只显示已推进数据，成交标记保留实际 Bid/Ask 价格 |
| 回放 | 播放为品牌蓝主动作，暂停共用位置；进度与状态靠近控制 | 进度只读，结束后仍可按最后报价平仓 |
| 下单 | 白色金额输入、USD 后缀、快捷金额选中态、浅语义方向按钮 | 显示真实成交报价、训练资金占用及禁用原因 |
| 持仓 | 浮动盈亏与细语义边线突出，平仓是主动作 | 盈亏由 engine 提供，写入成功后才反馈完成 |
| 成交记录 | 开平仓价格与时间各分两行，价格为主、时间为辅；手机详情可展开 | 所有报价、时间、盈亏与平仓原因完整保留 |

图表继续采用 ECharts，折线只配极浅纯色面积，K 线保留实体/空心及语义色。最新价标签只在最新帧处于观察范围时显示；用户观察旧区域时保持原范围。首次只有一根行情，不使用虚构走势或未来时间填满画布。

方向和盈亏分开表达。买涨、买跌同时保留动作、方向和报价；盈亏同时保留文字、正负号和币种。空持仓及空记录使用轻量图标、简短状态与下一步提示，不用大型插画占据练习空间。

## 5. 操作反馈与小屏阅读

动效用于说明显式操作：控件颜色过渡、按下反馈、帮助淡入、详情箭头旋转、交易结果反馈和只读进度推进。具体时长统一见 [产品与设计](01-product-and-design.md#视觉与图表)。报价和盈亏逐根即时更新，ECharts 不播放行情动画；减少动效时取消位移、缩放及过渡，反馈文字仍可读。

开仓保存成功后聚焦持仓标题，平仓成功后聚焦金额；屏幕外的目标就近滚入。写入失败定位持续错误区。该焦点流程使键盘和手机操作都能找到下一步。

小屏图表下方提供“去下单 / 查看持仓与平仓”入口，主动点击才定位，行情推进不抢焦点。账户按内容空间重排，手机时间轴按可用宽度减少标签；文字放大时仍能读到金额、错误及主要操作，避免将整张桌面画布缩成细小纹理。

当前输入、持仓、保存与回放状态的行为由 [状态与操作约定](01-product-and-design.md#状态错误与操作反馈) 统一维护；真实历史、CSV、完整备份及旧练习列表按既有阶段推进。

## 6. 实现与验证边界

该方案已接入实际 Vue 工作台，使用已有 Vue、Pinia、ECharts、本地 Inter、SVG 和原生 CSS，未增加依赖或改动 engine、store、storage 及数据库格式。业务参数统一见 [数据与交易](03-data-and-trading.md)，组件职责见 [架构](02-architecture.md)。

类型检查、构建、应用测试、响应式与文字放大检查的具体结果及限制统一记录在 [实际验证记录](04-roadmap-and-acceptance.md#4-实际验证记录)。研究、设计判断和运行验证分别记录；本次视觉检查不能推定历史样本、CSV、完整备份、系统性无障碍或物理断网已通过验收。

## 7. 独立样稿的用途

[交互样稿](05-interface-preview.html) 是前期构图参考，可直接用浏览器打开。它提供初始、持仓、平仓及保存失败等视觉场景，使用人工图形与固定数字，不执行训练交易、不写 IndexedDB，也不实现真实导出或完整金额校验。

样稿保留前期八列记录示意和场景切换工具；实际应用已使用六列两行记录，并加入真实的交易焦点流程。样稿的 SVG 与场景按钮用于说明设计，不作为正式图表或正式页面入口。

样稿测试与应用测试分别记录，不能互相替代。当前应用以产品文档与实际运行证据为准。
