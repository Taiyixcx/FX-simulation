## 1. 推荐方向：精密、轻盈、有反馈

将 FX 练习室做成一个有辨识度的**浅色精密交易工作台**：墨色品牌识别、明确的主报价、大幅图表、安静的账户概要、薄荷绿与陶红交易按钮，以及及时而短促的操作反馈。

用户进入后的视线路径是 **当前品种与报价 → 图表走势 → 下单或持仓结果 → 回放 → 成交记录**。权益负责说明资金状态，图表负责判断，右侧负责执行；每一块有自己的视觉权重。

精致感由五项具体变化形成：

1. **比例有主次。** 权益突出，其他账户数字较小；Bid 是主读数，Ask 仍明确可见；持仓时平仓成为交易区主动作。
2. **表面有层次。** 外围淡灰、主图纯白、交易区极浅灰，通过留白和细线区分职责。
3. **细节有统一尺度。** 数字、单位、图标、控件高度、分隔和对齐线使用同一组规则。
4. **操作有回应。** 悬停、按下、选中、输入、展开、开平仓各有短反馈，状态立即生效。
5. **边缘状态同样完整。** 首根行情、空持仓、无记录、保存失败、恢复暂停都保持一致的精致程度。

浅色主方向兼顾本机长时间看图和新手理解。大面积深色、玻璃折射、装饰渐变、卡片悬浮、持续呼吸灯、页面入场瀑布和庆祝动画不进入推荐方案。它们会增加视觉负担，也难以改善交易操作。

## 2. 改版前的问题与最终落点

已审查 `src/App.vue`、共享样式及账户、图表、回放、交易、记录、帮助组件，并在独立 Chromium 会话查看现有 1440px 页面。下面记录改版前的设计判断和本轮实际改动，不是竞品易用性或性能测评。

| 现状 | 对视觉的影响 | 本方案改变 |
| --- | --- | --- |
| 五个账户数字同字号、同间距、几乎等权 | 首屏像平均分栏的报表，难找到重点 | 权益与其他指标分级，单位独立，文字放大时提前重排 |
| Bid、Ask 都是 32px，同色同权 | 报价区缺少一个稳定主读数 | Bid 主读数、Ask 辅读数，点差独立；完整报价保留 |
| 品牌蓝同时用于大量文字、入口和选中 | 主色缺少稀缺性 | 墨色品牌；蓝色集中给播放、选中、焦点与当前价格 |
| 整片浅灰侧栏配两个红绿实色块 | 方向按钮压过持仓结果，颜色面积偏大 | 方向用浅语义底色；持仓盈亏与墨色平仓入口突出 |
| 图表、工具栏、回放虽然齐全，但读数较分散 | 有功能，缺少整体仪表感 | 品种栏、报价、读数、画布、回放成为一个连续区域 |
| 动效主要是背景和边框变色 | 状态转换缺少有目的的触感 | 固定反馈位置、短切换和展开过渡；数据保持即时 |
| 窄屏图表轴与桌面信息密度相同 | 小屏读数和操作更费力 | 减少轴标签数量，保持字体尺寸；按内容空间重排交易区 |

现有本地字体、SVG 图标、同一 ECharts 实例、无未来行情、手机成交详情、键盘帮助和减少动效支持继续作为基础。本轮已重做构图、层级和反馈，保留既有交易规则与数据边界。

## 3. 从大量设计中取什么

本次核对 **19 个官方页面，覆盖 9 个产品与 4 套设计体系**；完整短摘要、资料类型、核对方式和限制见 [界面设计研究](../knowledge/04-interface-design.md)。

| 参考组合 | 采用的手法 | 在本项目的落点 |
| --- | --- | --- |
| TradingView、Coinbase Advanced、IBKR | 看盘、执行、结果有稳定空间分工 | 主图 + 邻近交易区 + 下方成交记录 |
| Mercury、Wealthfront | 大数字与辅助数字有显著差别 | 权益、Bid 和持仓盈亏形成三处有条件的视觉重点 |
| Linear、Raycast | 控件紧凑、动作集中、弱化辅助区域 | 同一工具条内统一高度，说明按需打开，反馈贴近操作 |
| Koyfin、Stripe | 数据密度整齐、内容与动作共享上下文 | 记录列严格对齐，金额与单位分级，恢复动作就近提供 |
| Atlassian、Radix、Carbon、Apple | 有序状态色阶、短反馈、可访问性与动效边界 | CSS token、三种按钮层级、可见焦点、减少动效 |

上述产品的复杂导航、真实交易、云服务和新增分析能力不进入这次方案。官方示意图只用于研究构图，没有复制其界面资产或代码。

│                                               │ 成交价 / 时间   │
│ 播放 / 下一根 / 速度             进度 / 状态    │ 平仓（主动作）  │
├────────────────────────────────────────────┴────────────────────┤
│ 成交记录 / 数量 / 本次练习                                        │
│ 方向     名义金额     开仓信息     平仓信息     结算盈亏     原因  │

- 工作台按实际文字、图表和操作宽度完成构图；最终尺寸统一见 [产品与设计](01-product-and-design.md#p1-工作台布局)。1440×900 下报价、播放和持仓平仓处于首屏，成交记录继续向下。
- 用内容、容器查询与 rem 约束布局，不通过固定整页高度裁掉放大后的文字。
- 全页保持连续工作台，主要分区之间使用 1px 细线。交易区背景比主图深一档，静态工作区无需悬浮阴影。
- 不增加没有功能需要的左侧导航。成交记录可用同页锚点；数据管理入口等到对应能力实现后再接入。

## 5. 字体、色彩与形状

候选参数已收敛到实际应用，色阶、字号、控件和动效参数统一维护在 [产品与设计](01-product-and-design.md#视觉与图表)，本文件不再保存第二套有效参数。

数字及英文沿用本地 Inter，中文使用系统字体；单位、时间与主数字分级，等宽数字保证行情更新时稳定。主表面与浅灰交易区靠留白及细线连接，墨色品牌和持仓平仓突出关键动作，蓝色集中用于播放、选中、焦点及当前价格。方向和盈亏分别表达，盈亏始终保留文字、正负号与币种。

已定向核查辅助正文、主按钮文字、语义文字、输入边界及焦点的实际对比度；辅助分隔线不独自表达控件可用性。手机主要操作区放大，200% 文字下按可用空间重排。

## 6. 各模块的实际改动

### 品牌与全局状态

将品牌标识由普通蓝色块调整为墨色的小型 FX 标识，文字干净有力量。品牌栏左侧说明所在工作台，右侧集中记录锚点和本机保存状态。保存位置及宽度稳定，保存中不撑开布局；成功用小勾和文字，失败同时使用错误文字与持续可见的恢复区。

页面不出现设计自述、技术栈、外部产品品牌或未实现能力。样稿顶部的“设计样稿”和场景切换属于评审工具，正式页面不接入。

### 账户概要

权益是主要资金读数，余额、可用资金、资金占用保持可见但降低字号。持仓盈亏在概要条右侧单独分组，始终显示币种。交易侧栏再展示持仓盈亏用于执行判断，不在首屏另做重复账户卡片。

保持现有概念及计算，所有变化来自排列、字体与状态色。帮助按钮继续解释权益和资金占用；不加入未实现的权益曲线、收益率、胜率或资产配置图。

### 品种、报价和图表

品种、模拟来源、图表类型是一个紧凑顶部工具条。模拟标签写“模拟 · 1 分钟”，来源详情按需打开。未来真实历史模式只在对应功能实现后接入标签和来源说明。

Bid 占主视觉，Ask 放旁边，点差紧凑显示。两种报价都完整保留，方向按钮继续标示实际成交使用的 Ask 或 Bid。尾部两位的固定蓝色仅用于报价精度层次，不能作为涨跌信号。

图表使用四至六条低对比水平网格、清楚的右侧价格轴、稳定读数栏和当前价标签。折线可以配极浅的**纯色**面积，K 线保持实体/空心及红绿语义，切换不重建实例、不重置观察范围。首根只显示已存在的报价点和时间；不展示未来时间轴，不用示例走势填满初始画布。

开仓线、开平仓标记仍在实际成交价格。图表自动范围要包含 Ask 成交价；标记不能为了美观贴到 Bid 曲线上。最新价标签和轴标签碰撞时隐藏被覆盖的普通轴标签，不能把两个价格叠成一团。

样稿的 SVG 只说明构图，正式图表继续用 ECharts，保留十字线、缩放、平移、键盘导航、回到最新及资源释放。

### 回放

播放是唯一品牌蓝主动作；下一根为浅描边，速度为普通输入控件，进度和状态右对齐。播放与暂停共用同一位置和宽度。进度条高 3px、只读，表达已经推进的数量，不能画成可拖到未来的滑杆。

行情结束显示完成状态，禁用继续推进但允许按最后可见报价平仓。减少动效不影响按键或状态变化。

### 下单与持仓

金额区采用清楚的白色输入、USD 后缀、快捷金额选中状态和训练资金占用提示。买涨/买跌用语义色文字、浅底与细边框，减少大块红绿带来的廉价感，保留方向、动作和报价。

已有持仓时，方向按钮禁用，并在近处写明“当前已有持仓，请先平仓”；不能只靠透明度解释。当前持仓标题下方突出“浮动盈利 / 浮动亏损 / 持平”，配 2px 语义边线，后接开仓价、金额、时间。墨色平仓按钮是持仓时的主动作，动作完成后同位置显示简短结算反馈。

输入金额无效或资金不足时，就近保留具体错误与输入，字号与间距不因错误而挤压动作。业务仍由现有 store 与 engine 提供，视觉组件不另写盈亏或资金占用公式。

### 成交记录

桌面继续使用语义表格，数值右对齐，方向与原因左对齐。已将“开仓价 + 开仓时间”“平仓价 + 平仓时间”分别放在同一列内分两行，减少八列平均铺开；价格为主、时间为辅，结算盈亏明确写盈利/亏损和 USD。

两行单元格保留充足间距，并随文字自然增高。行 hover 只改变浅底色，不移动内容；本轮未添加成交行入场动画。无排序功能就不显示排序箭头，无备注能力就不画备注入口。

手机保留原有可展开详情，摘要为方向、金额、结果，展开显示报价、时间和原因。空记录用小图标、一行说明和下一步提示，避免大型插画占据练习空间。

实际应用已使用六列两行组织并放大手机操作区。独立样稿仍保留前期八列示意，不作为当前应用布局。

## 7. 动效规范：让操作有触感

已接入控件底色与边框过渡、按下反馈、帮助短淡入、交易结果短反馈、手机详情箭头旋转和只读进度推进。实际时长统一见 [产品与设计](01-product-and-design.md#视觉与图表)。恢复与重置不播放进度过渡，数据和交易立即生效。

只为显式操作做强调。最高速度每秒 10 根时，报价和盈亏不逐根闪烁，不滚动数字，不平滑插值；ECharts 保持 `animation: false`。减少动效时取消位移、缩放及过渡，反馈文字和状态仍完整可用。

开仓保存成功后聚焦持仓标题，平仓保存成功后聚焦金额；目标原本在屏幕外时就近滚入。交易写入失败定位持续错误区，不显示成功反馈。没有自动跳转、入场瀑布或庆祝动画。

## 8. 响应式与手机操作

| 有效空间 | 结构 | 关键要求 |
| --- | --- | --- |
| 桌面 | 主图 + 交易侧栏，账户概要横排 | 图表优先，播放和平仓首屏可见 |
| 平板与中桌面 | 图表全宽，下方下单与持仓并排 | 账户按内容空间重排，资金数据不隐藏 |
| 手机 | 账户、报价、图表/回放、交易/持仓、记录单列 | 主要操作触控区放大，记录详情可展开 |

最终断点统一见 [产品与设计](01-product-and-design.md#p1-工作台布局)。图表附近已加入“去下单 / 查看持仓与平仓”同页入口：无仓聚焦金额，有仓聚焦持仓标题。主动点击才定位，行情推进不抢焦点；文字放大时自然换行。独立样稿没有该真实焦点流程。

图表容器改变时，根据真实宽度计算绘图区，手机时间轴降低到约三至四个标签，文字尺寸保留。不能通过缩放完整桌面 SVG/画布让数字变成细小纹理。正文 200% 放大仍能完整读到错误、输入金额、播放和关闭持仓；页面本身不得横向溢出，记录表内允许必要滚动。

## 9. 状态与错误清单

| 状态 | 设计要求 |
| --- | --- |
| 读取中 | 保留品牌与稳定状态区，使用简短文字；不以假走势作占位 |
| 初次进入 | 暂停、首根报价、模拟来源、明确播放与单步；首根附近一条轻提示 |
| 已推进但无仓 | 图表正常，方向按钮可用，空持仓提示下一步 |
| 持仓盈利/亏损/持平 | 有文字、正负号、单位、语义色；平仓突出；禁用原因可读 |
| 输入错误/资金不足 | 输入旁原因，保留金额，关联 `aria-describedby` / `aria-invalid` |
| 保存中 | 保留状态区域宽度；按钮继续遵守现有忙碌规则，不重复成交 |
| 保存失败/冲突 | 持续错误区；暂停交易和推进；重试、导出等恢复动作按现有能力显示 |
| 平仓成功 | 账户、持仓、标记、记录一致更新；短反馈靠近原动作 |
| 行情结束 | 播放停止，明确结束，最后报价仍能平仓 |
| 重新打开/恢复 | 暂停状态，不自动重新播放 |
| 减少动效 | 内容与状态完整，取消动画，不丢反馈文字 |

备份恢复、CSV、历史样本、旧练习列表和三步引导仍按既有 P2–P4 安排。未来做这些界面时沿用相同控件和状态规则，不把尚未实现入口放入本轮实际页面。

不新增运行依赖。继续 Vue、Pinia、ECharts、本地 Inter、项目 SVG 和原生 CSS；这次方案无需另装动效库、组件库、字体或图标包。

## 11. 实际接入的验收标准

1. 在 1440×900 截取初始、已推进、播放、盈利、亏损、平仓、结束及错误状态，确认播放和平仓易找到。
2. 在 1024、768、390、360px 以及 200% 文字放大下完成下单、推进、平仓、查看详情；无整页横向溢出。
3. 键盘完成金额、快捷金额、买涨/买跌、回放、平仓、帮助开启/关闭；focus 可见、顺序合理、关闭返回焦点。
4. 原 ECharts 实例继续使用，类型切换保留缩放范围，Ask 标记价格正确，没有未来行情或未来结算。
5. 最高速度完整回放，确认没有持续闪烁或阻塞操作；减少动效时所有信息和状态可用。
