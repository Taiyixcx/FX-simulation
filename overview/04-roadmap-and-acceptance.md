## 2. 阶段实施顺序

### P0：规划与仓库

1. 将产品、工程、业务规则、路线与验收分别归并到四份 `overview/` 文档；知识依据移至 `knowledge/`，通用开发约束只在 [AGENTS](../AGENTS.md) 维护。
2. 删除迁移后的重复文件，修正导航、目录示例与文档同步映射。
3. 检查本次文本编码、命名、链接及业务冲突；配置忽略规则，排除依赖、产物、个人备份和未获公开授权的真实行情。
4. 核对目标远端当前状态，保留期间新增的提交；关联 Git 仓库，检查提交内容后正常同步，再核对远端文件。

### P1：基础交易

已建立 npm 工程、严格类型检查与 Vitest；纯 TypeScript 引擎负责模拟行情、开平仓、资金占用和结算。Pinia 协调统一进度，图表读取已推进帧，IndexedDB 事务保存一致会话。

已实现两品种生成行情、暂停/单步/速度控制、Bid 图表及实际成交标记。新练习随机生成种子，刷新校验并恢复原随机状态、余额和持仓，始终暂停。保存失败暂停并保留内存候选及原数据库，支持重试和当前快照导出；多窗口以当前指针版本拒绝陈旧覆盖。

旧练习数据保留，P1 界面仅显示当前成交。会话列表、备注、完整备份恢复与三步引导仍留在 P3；真实样本与 CSV 留在 P2。

### P2：历史回放

优先研究 HistData 双边 tick 的本机 M1 转换，按来源规则处理时区、分钟区间和末组报价，验证后登记样本证据。目标日期及训练点差见业务文档；下载和授权未落实时保留真实状态，不以生成数据替代历史样本。

完成 CSV 模板、全量校验与逐行错误提示；通过事务保存到 IndexedDB。历史模式复用 P1 交易引擎和图表接口，共用进度，处理来源标记、时间缺口、数据末尾以及切换会话。

### P3：复盘与体验

提供已保存会话列表、成交详情、纯文本备注及图表入口；备份恢复前全量校验，写入失败保留原记录。增加可跳过的三步引导和就地术语解释，完善保存状态、错误定位及恢复入口。

完成桌面与窄屏布局，检查焦点、按钮禁用条件、弹层返回焦点、文字放大和盈亏非颜色表达。产品界面只呈现练习需要的信息，研究和架构说明留在文档。

### P4：本机交付

按实际存在的 npm 脚本运行完整首版测试、类型检查和构建，提供双击 `start.cmd`；服务固定使用 `http://127.0.0.1:4173` 并严格检查端口。P1 已提供 npm 开发及构建预览命令，见根 [README](../README.md)，双击入口尚未实现。

在依赖及本机样本已准备、服务运行的条件下断网验证；运行不依赖外部字体、CDN、行情 API 或云服务。记录验收环境、结果和剩余限制，更新受影响文档。

## 3. 验收场景

纯业务单元测试使用 Vitest，真实浏览器关键流程使用 Playwright；人工检查覆盖视觉和可读性。场景描述是待执行标准，不是通过记录。

| 分组 | 关键输入或操作 | 验收预期 |
| --- | --- | --- |
| 数量与报价 | 分别用 Ask/Bid 开多空仓；名义金额除以入场价 | Decimal 数量及双边价格正确，1 pip 为 0.0001；不重复扣点差 |
| 账户一致性 | 开仓、重复估值、平仓；资金不足、第二次开仓 | 余额、权益、资金占用与记录吻合；无重复累积或半笔更新 |
| 边界结算 | `±0.005 USD` 舍入、重复点击平仓、权益耗尽及跳价负余额 | HALF_UP 得 `+0.01/-0.01`；只结算一次；当前可见报价结清并保留实际结果 |
| 模拟与进度 | 同种子重建、持仓中暂停及单步、切换播放速度 | 序列可复现；单步一根；图表、报价及估值同步；无遗留计时器 |
| 历史与未来 | 缩放、十字线、加速、切换来源、末尾再推进 | 只能访问已推进前缀；加速不跳过中间风控；末尾暂停仍可平仓 |
| 样本证据 | 核对原始文件、来源元信息及转换输出 | 实际覆盖、时区、报价和记录数可追溯；真实/训练 Ask 逐行可区分 |
| Tick 聚合 | 同分钟多 tick、边界 tick、空分钟、固定 EST 时间 | Bid OHLC 与末组 Bid/Ask 正确；边界归下一根；无假分钟、无夏令时误差 |
| CSV 正常导入 | 合法模板、明确时区、Ask 有/无及混合行 | 时间归一，M1 完成语义一致；源文件 Ask 或训练点差标注准确，真实性核验独立 |
| CSV 拒绝 | 缺列/值、非正/非有限价格、OHLC 错误、Ask < Bid、重复/乱序时间 | 行及字段错误明确；同一时刻的不同 UTC 偏移也判重；旧数据不变 |
| 快照与恢复 | 持仓刷新、关闭重开、历史/模拟继续、Decimal 往返 | 账户、持仓、记录和原数据源一致；随机状态可继续；派生值重算并暂停 |
| 存储与备份 | 写请求成功后事务中止、配额失败、损坏或缺源备份、取消覆盖 | 等待事务完成；失败不称成功、不清空原数据；重试不重复结算 |
| 文本安全 | 备注含 HTML、脚本或公式片段 | 按普通文本展示；不执行、不改变交易或存储行为 |
| 本机运行 | 双击启动、4173 占用、准备依赖和样本后断网 | 仅绑定固定本机地址；占用时报错；核心行情、交易、图表及保存可用 |
| 布局与输入 | 1440/1024/390px、键盘流程、200% 文字放大、首次引导跳过 | 关键控件可见、焦点明确、错误可定位；无整页横向溢出，仍能交易 |

### 固定数量的盈亏案例

下面均使用 `quantityBaseUnits = 1,000`，只作为引擎测试输入，不代表界面允许直接下数量订单。

| EUR/USD 案例 | 输入报价 | 预期已结算盈亏 |
| --- | --- | --- |
| 买涨后上涨 | 入场 Ask 1.1001，平仓 Bid 1.1010 | `+0.90 USD` |
| 买跌后下跌 | 入场 Bid 1.1000，平仓 Ask 1.0991 | `+0.90 USD` |
| 买涨即时平仓 | Bid/Ask 始终为 1.1000/1.1001 | `-0.10 USD` |
| 买跌即时平仓 | Bid/Ask 始终为 1.1000/1.1001 | `-0.10 USD` |
| 买涨方向有利但未覆盖点差 | 入场 Bid/Ask 1.1000/1.1001，平仓 Bid 1.10005 | `-0.05 USD` |
| 买跌方向有利但未覆盖点差 | 入场 Bid/Ask 1.1000/1.1001，平仓 Bid/Ask 1.09995/1.10005 | `-0.05 USD` |

另检验反方向亏损、不同名义金额以及开仓数量计算；平仓后的余额等于原余额加已结算盈亏，资金占用归零。
