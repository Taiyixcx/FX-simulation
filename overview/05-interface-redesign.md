## 1. 推荐方向：精密、轻盈、有反馈

将 FX 练习室做成一个有辨识度的**浅色精密交易工作台**：墨色品牌识别、明确的主报价、大幅图表、安静的账户概要、薄荷绿与陶红交易按钮，以及及时而短促的操作反馈。

用户进入后的视线路径是 **当前品种与报价 → 图表走势 → 下单或持仓结果 → 回放 → 成交记录**。权益负责说明资金状态，图表负责判断，右侧负责执行；每一块有自己的视觉权重。

精致感由五项具体变化形成：

1. **比例有主次。** 权益突出，其他账户数字较小；Bid 是主读数，Ask 仍明确可见；持仓时平仓成为交易区主动作。
2. **表面有层次。** 外围淡灰、主图纯白、交易区极浅灰，通过留白和细线区分职责。
3. **细节有统一尺度。** 数字、单位、图标、控件高度、分隔和对齐线使用同一组规则。
4. **操作有回应。** 悬停、按下、选中、输入、展开、开平仓各有短反馈，状态立即生效。
5. **边缘状态同样完整。** 首根行情、空持仓、无记录、保存失败、恢复暂停都保持一致的精致程度。

浅色主方向兼顾本机长时间看图和新手理解。大面积深色、玻璃折射、装饰渐变、卡片悬浮、持续呼吸灯、页面入场瀑布和庆祝动画不进入推荐方案。它们会增加视觉负担，也难以改善交易操作。

## 2. 当前页面的具体问题

已审查 `src/App.vue`、共享样式及账户、图表、回放、交易、记录、帮助组件，并在独立 Chromium 会话查看现有 1440px 页面。下面是设计判断，不是性能或易用性测评。

| 现状 | 对视觉的影响 | 本方案改变 |
| --- | --- | --- |
| 五个账户数字同字号、同间距、几乎等权 | 首屏像平均分栏的报表，难找到重点 | 权益 32px；其他指标 20px；持仓盈亏 24px |
| Bid、Ask 都是 32px，同色同权 | 报价区缺少一个稳定主读数 | Bid 40px，Ask 22px，点差 15px；报价仍完整 |
| 品牌蓝同时用于大量文字、入口和选中 | 主色缺少稀缺性 | 墨色品牌；蓝色集中给播放、选中、焦点与当前价格 |
| 整片浅灰侧栏配两个红绿实色块 | 方向按钮压过持仓结果，颜色面积偏大 | 方向用浅语义底色；持仓盈亏与墨色平仓入口突出 |
| 图表、工具栏、回放虽然齐全，但读数较分散 | 有功能，缺少整体仪表感 | 品种栏、报价、读数、画布、回放成为一个连续区域 |
| 动效主要是背景和边框变色 | 状态转换缺少有目的的触感 | 固定反馈位置、短切换和展开过渡；数据保持即时 |
| 窄屏图表轴与桌面信息密度相同 | 小屏读数和操作更费力 | 减少轴标签数量，保持字体尺寸；按内容空间重排交易区 |

现有本地字体、SVG 图标、同一 ECharts 实例、无未来行情、手机成交详情、键盘帮助和减少动效支持继续作为基础。重做的是构图、层级和反馈。

- 工作台最大宽度建议 1440px，外围常规 24px；大屏可评估放宽到现有 1600px。主内容边距 24–28px，内部分组间距 16–24px。
- 桌面交易区约 312–320px，图表占剩余空间。1440×900 下优先把报价、播放和持仓平仓放在首屏，成交记录可以继续向下。

- 全页保持连续工作台，主要分区之间使用 1px 细线。交易区背景比主图深一档，静态工作区无需悬浮阴影。
- 不增加没有功能需要的左侧导航。成交记录可用同页锚点；数据管理入口等到对应能力实现后再接入。

## 5. 字体、色彩与形状

以下为**候选设计参数**，还不是应用当前参数。接入应用时，将最终确认的参数合入 [产品与设计](01-product-and-design.md#视觉与图表)，本节随后改为引用，避免长期维护两套有效约定。

### 色彩

| 角色 | 候选色 | 使用位置 |
| --- | --- | --- |
| 页面背景 | `#F3F4F6` | 工作台外围 |
| 主表面 | `#FFFFFF` | 主图、账户、记录 |
| 辅助表面 | `#FBFCFD` / `#F7F8FA` | 交易区 / 普通控件背景 |
| 主文字 | `#18212E` | 品牌、标题、核心数值、平仓按钮 |
| 辅助文字 | `#667085` | 标签、时间、单位 |
| 普通分隔 | `#E4E7EC` | 区域分隔、表格横线 |
| 产品蓝 | `#325DEB` / `#EDF2FF` | 播放、焦点、当前选中 / 浅选中底 |
| 图表线 | `#4267DF` | Bid 折线；可搭配 `#F3F6FD` 纯色浅面积 |
| 盈利 / 买涨 | `#11765D` / `#EAF5F0` | 盈利文字、方向 / 轻底色 |
| 亏损 / 买跌 | `#B4484D` / `#FFF0EF` | 亏损文字、方向、异常 / 轻底色 |

盈亏同时展示“盈利 / 亏损 / 持平”、正负号、币种及颜色；方向和盈亏不混成一个概念。默认无仓状态保持中性，不把 0 显示为盈利。蓝色不表达涨跌，也不表示真实市场连接。

主色、盈利色与亏损色在白底及对应浅底上的正文对比度需达到 4.5:1；交互边界与焦点的必要对比需达到 3:1。浅分隔线仅承担辅助结构，不能独自表达输入可用性、错误或选中。开发阶段按实际组合核查。

### 文字与数字

应用继续使用已有的本地 Inter，中文优先系统字体；无需引入远程字体或另一个字体包。样稿为完全独立文件，使用系统字体，正式接入后以本地 Inter 复核字面宽度。

| 内容 | 建议大小 / 字重 | 要点 |
| --- | --- | --- |
| 主 Bid | 40px / 550–600 | 等宽数字，整串价格可读；尾部两位可用品牌蓝，不拆散数字 |
| Ask | 22px / 550 | 明确写“买入价 · Ask”，保留完整精度 |
| 权益 | 32px / 600 | 与其他账户数据有明显主次 |
| 持仓浮盈亏 | 32px / 550 | 带文字与正负号，单位弱化 |
| 其他账户数字 | 20px / 550 | 对齐统一，USD 12–13px |
| 品种 / 品牌 | 18px / 600–650 | 控制标题数量，避免装饰口号 |
| 区块标题 / 正文 | 16px / 600；14–16px / 400–500 | 提示、错误、操作文案优先可读 |
| 次要标签 / 时间 | 13–14px / 400–500 | 主要输入和关键动作标签至少 14px |
| 轴标签 / 轻徽标 | 12–13px | 手机减少数量，不能把整张图缩小压扁文字 |

以 rem 定义实际字号，金额和报价用 `font-variant-numeric: tabular-nums`。负字距只轻用于数字与英文，中文不套整段负字距。

### 控件与形状

- 间距用 4px 基数，主要使用 8/12/16/24/28/32。相同职责共用对齐线，单位不贴住数值。
- 工作台圆角 12px，按钮/输入 6–8px，徽标 4–5px。圆形仅用于品种识别或小状态点。
- 常规操作高 40px；金额输入约 58px；交易按钮可容纳方向与报价，约 72–76px；平仓至少 44px。手机主要点击区域至少 44×44px。
- 图标用现有项目 SVG，常规 16–18px，统一笔画。重要动作保留中文，不依赖图标猜意思。
- 普通表面无阴影；选中分段控件允许极轻 1px 阴影，帮助弹层允许小幅柔和阴影。

## 6. 各模块如何改

### 品牌与全局状态

将品牌标识由普通蓝色块调整为墨色的小型 FX 标识，文字干净有力量。品牌栏左侧说明所在工作台，右侧集中记录锚点和本机保存状态。保存位置及宽度稳定，保存中不撑开布局；成功用小勾和文字，失败同时使用错误文字与持续可见的恢复区。

页面不出现设计自述、技术栈、外部产品品牌或未实现能力。样稿顶部的“设计样稿”和场景切换属于评审工具，正式页面不接入。

### 账户概要

权益是主要资金读数，余额、可用资金、资金占用保持可见但降低字号。持仓盈亏在概要条右侧单独分组，始终显示币种。交易侧栏再展示持仓盈亏用于执行判断，不在首屏另做重复账户卡片。

保持现有概念及计算，所有变化来自排列、字体与状态色。帮助按钮继续解释权益和资金占用；不加入未实现的权益曲线、收益率、胜率或资产配置图。

### 品种、报价和图表

品种、模拟来源、图表类型是一个紧凑顶部工具条。模拟标签写“模拟 · 1 分钟”，来源详情按需打开。未来真实历史模式只在对应功能实现后接入标签和来源说明。

Bid 占主视觉，Ask 放旁边，点差紧凑显示。两种报价都完整保留，方向按钮继续标示实际成交使用的 Ask 或 Bid。尾部两位的固定蓝色仅用于报价精度层次，不能作为涨跌信号。

图表使用四至六条低对比水平网格、清楚的右侧价格轴、稳定读数栏和当前价标签。折线可以配极浅的**纯色**面积，K 线保持实体/空心及红绿语义，切换不重建实例、不重置观察范围。首根只显示已存在的报价点和时间；不展示未来时间轴，不用示例走势填满初始画布。

开仓线、开平仓标记仍在实际成交价格。图表自动范围要包含 Ask 成交价；标记不能为了美观贴到 Bid 曲线上。最新价标签和轴标签碰撞时隐藏被覆盖的普通轴标签，不能把两个价格叠成一团。

样稿的 SVG 只说明构图，正式图表继续用 ECharts，保留十字线、缩放、平移、键盘导航、回到最新及资源释放。

### 回放

播放是唯一品牌蓝主动作；下一根为浅描边，速度为普通输入控件，进度和状态右对齐。播放与暂停共用同一位置和宽度。进度条高 3px、只读，表达已经推进的数量，不能画成可拖到未来的滑杆。

行情结束显示完成状态，禁用继续推进但允许按最后可见报价平仓。减少动效不影响按键或状态变化。

### 下单与持仓

金额区采用清楚的白色输入、USD 后缀、快捷金额选中状态和训练资金占用提示。买涨/买跌用语义色文字、浅底与细边框，减少大块红绿带来的廉价感，保留方向、动作和报价。

已有持仓时，方向按钮禁用，并在近处写明“当前已有持仓，请先平仓”；不能只靠透明度解释。当前持仓标题下方突出“浮动盈利 / 浮动亏损 / 持平”，配 2px 语义边线，后接开仓价、金额、时间。墨色平仓按钮是持仓时的主动作，动作完成后同位置显示简短结算反馈。

输入金额无效或资金不足时，就近保留具体错误与输入，字号与间距不因错误而挤压动作。业务仍由现有 store 与 engine 提供，视觉组件不另写盈亏或资金占用公式。

### 成交记录

桌面继续使用语义表格，数值右对齐，方向与原因左对齐。建议将“开仓价 + 开仓时间”“平仓价 + 平仓时间”分别放在同一列内分两行，减少八列平均铺开；价格为主、时间为辅，结算盈亏明确写盈利/亏损和 USD。

常规单行可采用 48–52px；两行单元格采用约 64px 或自适应高度。行 hover 只改变浅底色，不移动内容。新记录可一次轻淡入或浅底强调。无排序功能就不显示排序箭头，无备注能力就不画备注入口。

手机保留原有可展开详情，摘要为方向、金额、结果，展开显示报价、时间和原因。空记录用小图标、一行说明和下一步提示，避免大型插画占据练习空间。

独立样稿保留八列表格以核对现有字段；持仓禁用原因已示意。六列两行组织和触控点击区放大属于正式接入时需要完善的细节。

## 7. 动效规范：让操作有触感

这些参数是本项目建议，来源给出的是原则和参考范围。

| 触发 | 建议动效 | 时长 | 边界 |
| --- | --- | --- | --- |
| 按钮/记录 hover | 底色与边框轻变 | 120–140ms | 只用于支持 hover 的设备，表格行不位移 |
| 按钮按下 | 底色加深；可选缩放至 0.985 | 80ms | 禁用无动效，触发逻辑立即执行 |
| 分段或快捷金额选中 | 选中底色短过渡 | 140–180ms | 不做长距离滑块，不等动画切换内容 |
| 术语说明出现 | 淡入，最多位移 4px | 160ms；退出 100ms | Escape 关闭并恢复焦点 |
| 持仓区/成交反馈 | 固定区域内淡入 | 160–180ms | 不改变交易按钮位置，不撒花 |
| 新成交行 | 单次浅底强调 | 180–220ms | 连续操作可合并反馈，不循环 |
| 进度推进 | 短线性宽度变化 | 100ms | 只读；重置和恢复立即定位 |
| 报价、账户、K线更新 | 即时显示 | 0ms | 不滚动数字、不平滑插值、不逐根闪烁 |
| 焦点环 | 立即显示 | 0ms | 2px 蓝环 + 间隔，不能为美观淡出 |

只为显式用户操作做强调；最高回放速度每秒 10 根时，不对每根价格和盈亏播放高亮。保持 ECharts `animation: false`，灵动来自操作与真实进度，不由装饰性数据动画制造。

普通过渡建议 `cubic-bezier(.2, .8, .2, 1)`；禁用弹跳和过冲。`prefers-reduced-motion: reduce` 下取消位置、缩放及过渡，直接呈现最终状态。初次进入不要求逐块延迟出现，恢复练习不重复入场动画。

样稿演示 CSS 控件反馈及状态切换；未接入真实回放调度、成交行入场或 Vue 状态过渡。

## 8. 响应式与手机操作

| 有效空间 | 结构 | 关键要求 |
| --- | --- | --- |
| 宽桌面，约 ≥1150px | 主图 + 312–320px 交易侧栏，五项账户一条概要 | 图表约占 70–75%，播放和平仓首屏可见 |
| 中桌面，约 960–1149px | 可暂用 288–300px 侧栏；若内容受挤压则提前改上下 | 以真实文字和图表可用宽度决定断点 |
| 平板，约 601–959px | 图表全宽，下方下单与持仓并排，账户分组 | 资金数据不隐藏，右侧持仓与输入之间细线分隔 |
| 手机，≤600px | 账户、报价、图表/回放、交易/持仓、记录单列 | 边距 16px；主操作至少 44px；详情可展开 |

手机的核心改进是**近处可到达的交易操作**。正式接入时增加图表附近的“去下单 / 查看持仓”同页入口：有仓优先指向持仓与平仓，无仓指向金额。入口使用锚点与焦点定位，无自动跳转，不因行情推进抢焦点；文字放大时自然换行。比覆盖内容的固定交易栏更稳妥。样稿尚未加入该入口。

图表容器改变时，根据真实宽度计算绘图区，手机时间轴降低到约三至四个标签，文字尺寸保留。不能通过缩放完整桌面 SVG/画布让数字变成细小纹理。正文 200% 放大仍能完整读到错误、输入金额、播放和关闭持仓；页面本身不得横向溢出，记录表内允许必要滚动。

## 9. 状态与错误清单

| 状态 | 设计要求 |
| --- | --- |
| 读取中 | 保留品牌与稳定状态区，使用简短文字；不以假走势作占位 |
| 初次进入 | 暂停、首根报价、模拟来源、明确播放与单步；首根附近一条轻提示 |
| 已推进但无仓 | 图表正常，方向按钮可用，空持仓提示下一步 |
| 持仓盈利/亏损/持平 | 有文字、正负号、单位、语义色；平仓突出；禁用原因可读 |
| 输入错误/资金不足 | 输入旁原因，保留金额，关联 `aria-describedby` / `aria-invalid` |
| 保存中 | 保留状态区域宽度；按钮继续遵守现有忙碌规则，不重复成交 |
| 保存失败/冲突 | 持续错误区；暂停交易和推进；重试、导出等恢复动作按现有能力显示 |
| 平仓成功 | 账户、持仓、标记、记录一致更新；短反馈靠近原动作 |
| 行情结束 | 播放停止，明确结束，最后报价仍能平仓 |
| 重新打开/恢复 | 暂停状态，不自动重新播放 |
| 减少动效 | 内容与状态完整，取消动画，不丢反馈文字 |

备份恢复、CSV、历史样本、旧练习列表和三步引导仍按既有 P2–P4 安排。未来做这些界面时沿用相同控件和状态规则，不把尚未实现入口放入本轮实际页面。

1. 在 1440×900 截取初始、已推进、播放、盈利、亏损、平仓、结束及错误状态，确认播放和平仓易找到。

3. 键盘完成金额、快捷金额、买涨/买跌、回放、平仓、帮助开启/关闭；focus 可见、顺序合理、关闭返回焦点。
4. 原 ECharts 实例继续使用，类型切换保留缩放范围，Ask 标记价格正确，没有未来行情或未来结算。
5. 最高速度完整回放，确认没有持续闪烁或阻塞操作；减少动效时所有信息和状态可用。
6. 校核实际文字、交互边界和焦点色组合；无色彩单独传义、轴标签遮挡或触控目标过小。
7. 确认运行资源均来自本机；保存错误及多窗口冲突不覆盖原数据。
8. 按实际代码变化执行现有类型检查、相关浏览器流程与构建；只有业务逻辑变化才补充必要单元测试。结果记录到 [路线与验收](04-roadmap-and-acceptance.md)。
