# 行情、交易与本地数据

本文是业务默认值、报价和账户公式、CSV 接口及保存规则的唯一维护位置。产品交互见 [产品与设计](01-product-and-design.md)，接口职责见 [架构](02-architecture.md)，实施状态及验证记录见 [路线与验收](04-roadmap-and-acceptance.md)。资料依据与适用限制见 [外汇与回放知识](../knowledge/01-forex-and-replay.md)。

## 1. 首版默认与训练边界

| 项目 | 约定 |
| --- | --- |
| 品种与记账 | EUR/USD、GBP/USD；账户以 USD 记账 |
| 初始余额 | 每个独立练习 10,000 USD |
| 持仓 | 同时一笔；手动开仓和平仓，不加减仓、挂单或借款 |
| 交易金额 | 100、500、1,000 USD 快捷值；可输入正数，最多两位小数 |
| 资金限制 | 开仓名义金额不超过当时可用资金，不提供杠杆选项 |
| 默认进入 | EUR/USD 模拟模式、暂停、Bid 折线；可切换 Bid K 线 |
| 回放控制 | 暂停、下一根；每秒推进 1、5、10 根完成的 M1 行情 |
| 成交成本 | 只体现 Bid/Ask 点差，不另计佣金、滑点和隔夜费 |
| 时间 | 内部 UTC 毫秒；界面 Asia/Shanghai（UTC+8） |

这是认识方向、报价和盈亏的训练头寸，不是兑换并持有多币种现金的真实账户。名义金额用于计算数量及训练资金占用，不表示最大亏损，也不等同于经纪商保证金。真实历史报价与训练成交规则分别标注；首版不声称还原真实流动性、逐笔执行或完整强平制度。

## 2. 行情来源与样本准备

### 模拟行情

生成器输出已完成的分钟 Bid OHLC 与训练 Ask。相同生成器版本、配置、种子和进度必须得到相同序列；保存随机状态以便继续。趋势、震荡与波动变化均为生成数据，页面统一标为“模拟行情”，不添加虚构新闻或成交量。

### 真实历史

优先准备两种品种各一个交易周，目标为 2024-03-04 至 2024-03-08。样本实际取得、覆盖和校验结果登记在本文件关联的 [阶段记录](04-roadmap-and-acceptance.md)；目标日期不代表文件已经存在。

首选研究 HistData **Generic ASCII 双边 tick**，在本机聚合成 M1。其 M1 OHLC 文件只有 Bid；双边 tick 才提供 Bid/Ask。来源时间按固定 EST（UTC−5）转 UTC，不应用纽约夏令时规则。转换流程如下：

1. 校验原始 tick 的时间、正价格和 Bid/Ask 关系，保留原始顺序及精度；来源异常必须报告。
2. 按 UTC 分钟区间 `[minuteStart, minuteStart + 60秒)` 分组。边界 tick 归入下一分钟。
3. 以该分钟 Bid 的首值、最高、最低、末值生成 OHLC，保留分钟内最后一组 Bid/Ask。
4. 输出时间为区间结束时刻；没有 tick 的分钟不补行，不伪造逐笔路径或成交量。
5. 对输出执行与 CSV 导入相同的校验，记录转换版本、输入和输出校验信息。

格式依据为 [HistData 文件说明](https://www.histdata.com/f-a-q/data-files-detailed-specification/)；数据记录的是该来源的报价，不是覆盖整个分散外汇市场的唯一价格。Dukascopy 保留为候选，自动抓取、本地数据库及公开再分发的适用授权仍需核实，未核实前不实施相应方式。

每个数据集元信息包含来源名称和链接、品种、实际 UTC 起止时间、原始时区、周期、报价类型、转换说明及版本、记录数、文件校验信息和使用许可核对情况。源文件提供 Ask、Bid 加训练 Ask、混合行来源必须可区分；数据真实性由来源核验独立说明。

本机随应用使用的样本放在 `public/data/`；原始下载文件与真实行情 CSV 默认不提交 Git。公开仓库可提交来源说明、元信息、转换工具及明确标为生成的测试样例。取得明确再分发权限后，才调整相应文件的提交规则。用户导入保存到 IndexedDB，不写回源码目录。

## 3. CSV 接口与校验

一份文件对应一种货币对，由导入界面明确选择。表头为 `timestamp,open,high,low,close[,ask]`：OHLC 均为 Bid，`close` 是当前可用 Bid，`ask` 是分钟结束时使用的 Ask，不是 Ask OHLC。

```csv
timestamp,open,high,low,close,ask
2024-03-04T08:01:00Z,1.10000,1.10040,1.09980,1.10020,1.10035
```

以上是生成的格式示例，不是真实样本。首版接受已规范化的 M1 CSV，其他源格式使用本机转换工具，不增加通用字段映射界面。

| 校验项 | 规则 |
| --- | --- |
| 时间 | 带 `Z` 或明确 UTC 偏移的 ISO 8601，表示分钟完成时刻；转换后为完整分钟边界 |
| 顺序 | UTC 时间严格递增；重复、乱序、非法时间或缺少时区均拒绝，不猜测本机时区、不静默排序 |
| Bid OHLC | 必填、正的有限十进制数；`low ≤ open/close ≤ high` 且 `low ≤ high` |
| Ask | 非空时为正的有限十进制数且 `ask ≥ close`；缺列或空单元格按训练点差处理 |
| 文件 | 必需列与每行列数正确，至少一条有效行情；错误可定位到行和字段 |
| 缺口 | 保留休市或源缺口，不插值、不补假分钟；推进时显示实际跨越的时间 |
| 写入 | 全量通过后事务写入；失败不改变当前会话或已有数据集 |

来源若用分钟开始时间标记 OHLC，转换工具须先加一分钟；不得提前拿到尚未完成的收盘值。完成时刻同为 `08:01:00Z` 和 `16:01:00+08:00` 的两行属于重复记录。

内部使用 `timestampMs`；只在图表适配处转换为 `timeSec`。价格从字符串进入 Decimal，不先做普通浮点运算。

## 4. 报价与统一回放进度

图表只绘制 Bid，交易区同时显示卖出价 Bid 和买入价 Ask。开仓线显示实际成交价，包括做多时的 Ask，不能把它误标为 Bid。

| 品种 | 1 pip | 缺少 Ask 时的训练点差 | Ask 计算 |
| --- | --- | --- | --- |
| EUR/USD | 0.0001 | 1 pip | `askPrice = bidPrice + 0.0001` |
| GBP/USD | 0.0001 | 1.5 pip | `askPrice = bidPrice + 0.00015` |

源文件提供的 Ask 直接使用；缺失行才生成训练 Ask，逐行保留报价来源。是否为真实提供商报价另由来源核验说明，不能仅凭存在 Ask 列宣称真实性。混合数据不能整体标成真实双边报价；训练点差不能描述为该历史时刻的真实点差。小数第五位是报价精度，不等于一 pip。

图表、当前报价、成交和账户估值共用一个会话进度。初始只提供第一根完成行情；以后仅将已推进前缀传给图表，缩放和十字线也不能访问未来。暂停时行情不变，可按当前报价交易；“下一根”只推进一根。加速逐根更新及检查资金耗尽，不能只取最后一根跳过中间状态。

每秒 1／5／10 根表示回放进度，不表示分钟内的真实 tick 路径。数据结束自动暂停并禁止继续推进，仍可用最后报价平仓；从头练习创建新会话，保留旧记录。暂停、切换或卸载后不能遗留第二套回放计时器。

## 5. 交易与账户计算

### 数量与盈亏

开仓输入 `notionalUsd` 必须有效、为正、按美元分输入且不超过 `availableFundsUsd`。已有持仓时拒绝第二次开仓。以下 `quantityBaseUnits` 对应 EUR 或 GBP 的基础货币数量，USD 为报价货币，因此盈亏无需额外汇率换算。

| 方向 | 成交及数量 | 当前浮动盈亏 |
| --- | --- | --- |
| 买涨（做多） | Ask 开仓；`quantityBaseUnits = notionalUsd / entryAskPrice` | `(bidPrice - entryAskPrice) * quantityBaseUnits` |
| 买跌（做空） | Bid 开仓；`quantityBaseUnits = notionalUsd / entryBidPrice` | `(entryBidPrice - askPrice) * quantityBaseUnits` |

多头持仓以当前 Bid 平仓，空头持仓以当前 Ask 平仓。点差已体现在公式中，不再扣一笔点差费用；可展示预计成本作为解释。报价方向有利但变化不足以覆盖点差时，结果仍可能亏损。

引擎使用 Decimal.js，设置 **40 位有效数字、`ROUND_HALF_UP`**。金额、报价、数量由十进制字符串构造；中间数量和浮动盈亏不为显示而截断。平仓时才将实际盈亏舍入到美元分，余额按分记账。展示浮动盈亏可舍入，但展示值不能回写账本。

### 资金占用与结算

| 字段 | 含义或计算 |
| --- | --- |
| `balanceUsd` | 已结算余额；开仓不扣除名义金额，平仓加上已结算盈亏 |
| `reservedFundsUsd` | 持仓名义金额；无持仓时为零 |
| `unrealizedPnlUsd` | 按当前可平仓一侧报价计算的浮动盈亏；无持仓时为零 |
| `equityUsd` | `balanceUsd + unrealizedPnlUsd` |
| `availableFundsUsd` | `max(0, equityUsd - reservedFundsUsd)` |

一次平仓同时结算余额、释放资金占用、写入成交记录并清除持仓。重复点击只能产生一次结算；失败不得留下半笔交易。累计浮动盈亏每次由入场价和当前价重算，不逐帧叠加。

`equityUsd ≤ 0` 时，按当前可见报价结清持仓并暂停。跳价造成负结算余额时保留实际结果，不改成零、不使用未来价格、不提供贷款；用户可创建新的独立练习。这是训练停止规则，不代表真实经纪商的追缴或负余额保护。

## 6. 会话、保存与恢复

切换模式、品种或数据集先暂停并保存旧练习，新练习资金独立。恢复旧会话使用原始来源，不将持仓转接到另一段价格序列。

一致快照保存版本、会话标识、品种和模式、数据集标识及校验信息、历史进度或生成器版本/配置/随机状态、当前可见报价、已结算余额、持仓、成交及备注。Decimal 序列化为十进制字符串；资金占用、权益和可用资金由引擎重算，不信任旧展示值。恢复及重新打开后始终暂停。

交易、导入、恢复等关键操作先生成待提交状态，校验后事务写入；只有 IndexedDB **事务完成**才报告保存成功，不能仅凭单个写请求成功。自动快照必须保存同一时刻的账户、持仓和行情，避免不同版本拼接；恢复以最近成功快照为准。

保存失败暂停推进和相关操作，保留已有数据库及未保存的内存状态，提供重试或备份入口。重试不得重复结算同一交易，也不得把未完成保存显示为成功。存储实施依据见 [前端与本地存储知识](../knowledge/02-web-engineering.md)。

备份包含格式版本、会话和记录，以及恢复所需的导入数据或可校验的本机数据集标识。恢复前全量验证版本、数值、持仓、进度及数据集可用性；损坏、缺失或不支持的内容不得部分覆盖。覆盖、清空需用户明确选择，取消则原数据不变。备注及导入内容按普通文本显示，不执行代码或通过 `v-html` 渲染。
